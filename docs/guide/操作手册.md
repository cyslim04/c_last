# Trust Work 操作手册

本文档面向系统管理员、开发者和客户，说明从首次部署到日常业务操作的完整步骤。

## 一、使用前准备

### 1. 环境要求

- Windows 10/11
- GCC 和 SQLite3 开发库（用于编译后端）
- Node.js 18 或更高版本（用于运行前端）
- 支持账户切换的浏览器钱包插件，例如 MetaMask（需要链上存证时使用）

### 2. 初始化首个管理员

首次使用且数据库中没有用户时，在 PowerShell 中执行：

```powershell
cd C:\Users\yce\Desktop\c_last\backend
.\init-admin.ps1
```

按提示输入管理员账号和密码。密码以安全输入方式读取，不会显示在屏幕上。

注意：数据库已有任意用户后，初始化命令会拒绝执行。忘记管理员密码时，应由已有管理员在“成员管理”中重置，或按组织的数据恢复流程处理。

## 二、启动和停止系统

### 1. 启动后端

打开第一个 PowerShell 窗口：

```powershell
cd C:\Users\yce\Desktop\c_last\backend
.\run.ps1
```

看到 `Trust Work backend running at http://localhost:8080` 后，后端已启动。该窗口需要保持打开。

`run.ps1` 会先编译后端，并停止同路径下已运行的旧服务，因此可以直接重复执行。

### 2. 启动前端

打开第二个 PowerShell 窗口：

```powershell
cd C:\Users\yce\Desktop\c_last\frontend
npm install
npm run dev
```

浏览器访问 `http://localhost:5173`。首次安装依赖时执行一次 `npm install` 即可。

如果页面操作提示“无法连接后端服务”或旧版本显示 `Failed to fetch`，先确认后端 PowerShell 窗口仍在运行，并在浏览器打开 `http://localhost:8080/api/health`。只有返回后端运行状态后，再刷新前端页面重试。前后端不在同一台机器时，需要在前端启动前设置 `VITE_API_BASE` 为实际后端地址。

### 3. 停止系统

- 前端：在前端 PowerShell 窗口按 `Ctrl+C`。
- 后端：在后端 PowerShell 窗口按 `Ctrl+C`；如果窗口已关闭，可重新执行 `run.ps1`，脚本会先结束旧进程。

## 三、管理员操作

### 1. 登录

使用初始化时创建的管理员账号和密码登录。系统不提供公开注册和快捷账号入口。

### 2. 管理成员

进入“成员管理”：

页面顶部显示当前登录管理员身份；选择成员后，下方区域会标记为“正在维护成员”，用于区分被编辑的开发者或客户账号。

1. 选择新增角色：开发者或客户。
2. 填写用户名、初始密码和资料；初始密码必须由管理员明确设置。
3. 保存后，将账号和初始密码安全告知对应成员。
4. 需要停用账号时，使用“停用”；恢复使用时选择“启用”。
5. 成员忘记密码时，选择“重置密码”并通知新密码。

已参与项目的成员通常不能直接删除，应先处理项目关联关系；停用不会删除历史工时、交付物或审计记录。

### 3. 创建项目

进入“新增项目”：

1. 填写项目名称和项目说明。
2. 选择一个已启用的开发者。
3. 选择一个已启用的客户。
4. 保存项目。

项目创建后，可在“项目管理”查看状态、成员和阶段进度。

### 4. 查看项目和流程

- “项目管理”：按项目状态、开发者和客户筛选项目。
- “流程总览”：查看项目当前阶段、客户确认、阶段审计和最终审计门禁。
- “审计管理”：处理待阶段审计、待最终审计，并查看链上记录和操作日志。

### 5. 阶段审计与最终审计

1. 进入“审计管理”。
2. 在“待阶段审计”中选择项目，核对工时、交付物和客户意见。
3. 填写审计意见，选择通过或驳回。
4. 所有阶段均通过后，在“待总审计项目”中选择项目。
5. 核对项目整体记录，填写最终结论并提交。

驳回阶段会将项目退回开发者继续补充工时或交付物；审计记录提交后会保留在项目历史中。

## 四、开发者操作

### 1. 绑定钱包（可选）

需要提交链上存证时：

1. 安装并解锁 MetaMask。
2. 登录系统后，点击顶部的钱包状态按钮。
3. 点击“连接 MetaMask”，授权当前账户。
4. 确认网络为 Sepolia 或本地 Hardhat。

钱包只用于链上操作，不影响普通账号登录。切换账户或网络后，重新检查顶部钱包状态。

### 2. 登记工时

进入“工时记录”：

1. 选择所属项目。
2. 填写工作日期、工时和任务说明。
3. 点击“生成工时摘要”。
4. 在历史记录中核对阶段、摘要和状态。
5. 钱包已连接且网络受支持时，可点击“提交链上存证”。

工时会自动归入项目当前阶段。当前阶段等待客户确认或管理员审计时，系统会根据流程规则限制继续登记。

### 3. 登记交付物

进入“交付物”：

1. 选择所属项目并填写版本号。
2. 选择要交付的文件。
3. 填写交付说明。
4. 系统在浏览器中计算文件 SHA-256 哈希。
5. 点击“登记交付物”。
6. 需要链上留痕时，连接钱包后点击“提交链上存证”。

文件哈希用于确认文件是否被替换；系统保存的是文件信息和哈希，不会自动替代组织内部的文件分发流程。

## 五、客户操作

### 1. 查看待确认阶段

进入“客户确认”，选择待处理阶段，查看：

- 本阶段工时历史
- 最新交付版本和文件哈希
- 开发者交付说明
- 之前的确认信息

### 2. 确认或驳回

1. 填写确认意见；驳回时必须说明原因。
2. 连接支持的钱包（如系统要求链上确认）。
3. 点击“确认通过”或“驳回修改”。
4. 刷新页面，确认阶段状态已更新。

通过后项目进入管理员阶段审计；驳回后返回开发者修改。

## 六、个人资料和安全

进入“个人中心”可以：

- 修改姓名、邮箱、手机号、公司或团队、个人简介
- 上传头像
- 修改当前登录密码
- 查看钱包连接状态
- 退出当前会话

修改密码后，下一次登录必须使用新密码。不要在聊天记录、代码仓库或截图中保存密码和私钥。

## 七、日常检查与故障排查

### 后端无法启动

1. 确认 8080 端口未被其他程序占用。
2. 重新执行 `backend\\run.ps1`。
3. 如果编译失败，检查 GCC 和 SQLite3 路径是否与 `backend\\build.ps1` 配置一致。

### 前端无法请求接口

1. 确认后端窗口仍在运行。
2. 浏览器打开 `http://localhost:8080/api/health`，应返回后端运行状态。
3. 若前端使用其他后端地址，设置 `VITE_API_BASE` 后重新启动前端。

### 登录失败

- 检查账号是否拼写正确。
- 检查账号是否已被管理员停用。
- 确认使用的是最新密码。
- 空数据库必须先执行一次 `init-admin.ps1`。

### 无法提交链上存证

- 检查 MetaMask 是否已安装、解锁并连接当前页面。
- 检查当前网络是否为 Sepolia 或本地 Hardhat。
- 检查钱包账户是否与当前操作角色匹配。
- 普通业务登记不依赖钱包；可先保存业务记录，稍后再提交链上存证。

### 数据备份

停止后端后，复制 `backend\\data\\trust_work.db` 进行备份；头像文件位于 `backend\\uploads\\avatars\\`，需要与数据库一并备份。恢复前先停止服务，并保留原文件副本。

## 八、开发验证命令

```powershell
cd frontend
npm run build

cd ..\backend
.\build.ps1

cd ..\contracts
npm run test
```

合约测试需要先在 `contracts/` 执行 `npm install`。生产部署不要使用仓库中的测试账号或私钥。
